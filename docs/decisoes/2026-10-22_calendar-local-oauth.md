# Calendar local: cofre Linux e consentimento próprio

Estado: aceito para o recorte local, sem conta Google real verificada. RF-05/RF-12 permanecem parciais; RNF-02/RNF-05 orientam as fronteiras.

A API local opta explicitamente por Secret Service via `secret-tool`, separado do keyring de login do Tauri. A chave combina namespace Calendar e hash do proprietário autenticado; refresh tokens trafegam por stdin/pipe e access tokens permanecem em memória. Não adicionamos dependência nativa Node nem gravamos tokens no DynamoDB/frontend. A execução exige sessão Linux com Secret Service desbloqueado e um único processo da API; Lambda não recebe esse adaptador. Secret Service da sessão protege o armazenamento local, mas não constitui isolamento entre processos comprometidos do mesmo usuário do sistema.

Tauri administra navegador, PKCE S256, loopback efêmero, timeout e espera cancelável. O código/verifier vão do Rust à API local. O login concede identidade; Calendar pede consentimento separado com escopo owned.readonly ou owned, conforme escolha explícita. State é consumido atomicamente no repositório antes da troca. Conectar/desconectar usam fila por proprietário no processo local para que desconectar não conclua antes de remover um grant ainda em troca; habilitar múltiplas instâncias exige coordenação persistida. Não presumimos que uma fila em memória resolva essa implantação futura.

Há um ponto explícito de conclusão: ao iniciar POST connection, o Tauri sinaliza “Finalizando autorização” e a UI remove Cancelar. Cancelamento nessa fase é recusado também no comando nativo; o usuário pode desconectar depois. Uma resposta perdida ou logout durante esse POST não garante revogação. Desconectar revoga por melhor esforço e remove credencial/cadastro/espelhos; cópias enviadas permanecem no Google. Não há transação entre cofre, DynamoDB e Google; falhas locais continuam visíveis e exigem conferência do estado/retry.

A carga inicial é uma janela limitada de 30 dias passados e 366 futuros. Com `singleEvents=true`, um futuro ilimitado expandiria recorrências sem fim e atingiria o teto de 40 páginas. Incrementais omitem `timeMin`/`timeMax`; não prometemos um espelho completo nem avanço automático da janela. Somente `primary`, sob demanda; sem jobs/watch.

Escrita usa PATCH/If-Match para preservar campos remotos fora do formulário. Espelhos truncam textos apenas para exibição; campos inalterados são omitidos para não reenviar a versão truncada. Converter hora/dia inteiro limpa o tipo incompatível via null. Exclusão de cópia refletida mantém o vínculo local até o DELETE condicional, permitindo retry após falha local ou edição concorrente. A fila web só considera reflexão ativa/solicitada concluída quando `inSync` é verdadeiro e preserva `GOOGLE_CONFLICT` mesmo com conteúdo local igual.

Referências oficiais consultadas em 2026-10-22: [OAuth Desktop](https://developers.google.com/identity/protocols/oauth2/native-app), [events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list), [events.patch](https://developers.google.com/workspace/calendar/api/v3/reference/events/patch). Prova com o provedor depende de autorização específica futura; nenhum cofre, credencial ou calendário pessoal foi usado nesta frente.
